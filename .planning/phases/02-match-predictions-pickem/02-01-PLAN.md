# Plan 02-01: Database Schema, APIs, and Pick'em Frontend

Implement the database layer, prediction grading business logic, anonymous tracking, API endpoints, fixture card interactive pick selectors, and a complete leaderboard UI.

## Proposed Changes

### Database Layer
- **File**: [schema.prisma](file:///c:/Off%20work/wc2026/prisma/schema.prisma) [MODIFY]
  - Define a new `User` model with `deviceId` (unique), `nickname` (optional), `points` (default 0), and a relation to `Prediction`.
  - Define a new `Prediction` model with `userId`, `matchId`, `homeScore`, `awayScore`, `pointsEarned` (nullable to represent ungraded matches), and timestamps.
  - Implement a unique composite constraint `@@unique([userId, matchId])` to guarantee a single prediction per match per user.

### Business & Grading Logic
- **File**: [gradePredictions.ts](file:///c:/Off%20work/wc2026/lib/gradePredictions.ts) [NEW]
  - Implement scoring calculations comparing actual match scores (`homeScore`, `awayScore`) with user guesses.
  - Assign +3 points for exact scorelines, +1 point for a correct outcome (win/loss/draw match), and 0 points otherwise.
  - Update user's aggregate `points` correctly.

### Backend REST Endpoints
- **File**: [route.ts](file:///c:/Off%20work/wc2026/app/api/predictions/route.ts) [NEW]
  - `POST`: Submit/upsert score prediction. Ensures match is still `SCHEDULED` (throws error otherwise). Retrieves the user by parsing `wc2026_device_id` cookie.
  - `GET`: Fetch all predictions made by the active user.
- **File**: [route.ts](file:///c:/Off%20work/wc2026/app/api/leaderboard/route.ts) [NEW]
  - `GET`: Fetch the top 50 users sorted by total points descending.
